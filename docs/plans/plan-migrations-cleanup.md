# Plan: Migration Cleanup — fix down migration and schema consistency

> Source PRD: n/a (from /cleanup report on `database/migrations/`, 2026-06-12)

## Goal

Fix all findings from the cleanup review of `database/migrations/`: one real bug
(the down migration fails), one lying comment, two redundant indexes, and a batch
of consistency drift (SERIAL vs IDENTITY, INTEGER vs INT, VARCHAR vs TEXT,
`OR REPLACE`, whitespace, abbreviated index names). Additionally: add the missing
column comments and guard the down migration against silent regressions.

## Architectural decisions

Durable schema conventions this plan enforces (and future schema work follows):

- **Identity columns**: `INT GENERATED BY DEFAULT AS IDENTITY` — never `SERIAL`.
- **String columns**: `TEXT` — never `VARCHAR(n)`.
- **Integer spelling**: `INT` — not `INTEGER`.
- **DDL in the initial migration**: plain `CREATE` (no `OR REPLACE`, no
  `IF NOT EXISTS`) — unexpected pre-existing state must fail loudly.
- **Index names**: `idx_<table>_<columns>` with unabbreviated column names.
- **Documentation**: every table and every column carries a `COMMENT ON`.

## Resolved decisions

- **No production databases exist** — both migration files are edited in place;
  existing local dev DBs are reset via `make down && make dev` (standard per
  AGENTS.md).
- **Admin one-time-password hardening is out of scope** — tracked as a separate
  task (see Risks). This plan only fixes the comment that misdescribes the INSERT.
- **Missing column comments are in scope** — `tisch_sessions` (all 11 columns)
  and `tse_signaturen` (6 uncommented columns) get `COMMENT ON` statements,
  matching the file's convention.
- **test-integration.sh gets an up→down→up roundtrip** — unmasked, right after
  the existing `migrate up`, so a broken down migration fails the integration run.
  The cleanup trap at line 14 keeps its `|| true` (it must tolerate a missing DB).
- **Index renames**: `idx_kassenjournal_ks_nr` → `idx_kassenjournal_kassensitzung_nr`,
  `idx_tisch_sessions_ks_nr` → `idx_tisch_sessions_kassensitzung_nr`.

## Open questions / Risks

- **Default admin one-time password (separate task, not in this plan):** the up
  migration ships the same Argon2id hash (`m=64,t=2,p=2`) for a 6-digit numeric
  one-time password in every installation — offline-crackable from the public
  repo. Any install that has not completed the admin's first login is exposed.
  Candidate home: the first-run/onboarding flow (see `docs/plans/plan-tse-setup-wizard.md`
  for the related setup-wizard work) or a backend-generated OTP logged once at
  first startup.
- Editing the applied `01` migration means every existing dev database is stale;
  collaborators must reset (`make down && make dev`). No tooling breakage:
  golang-migrate tracks only the version number, not file checksums.

### What to build

Apply the full consistency batch to `01_initial.up.sql`, then prove the schema is
semantically unchanged for the application:

1. Correct the admin-user comment to state what the INSERT does (one-time
   password set, regular password NULL until first login).
2. Delete `idx_users_username` and `idx_tisch_favoriten_user_id`.
3. Drop `OR REPLACE` from all eleven function definitions.
4. Convert the three `SERIAL` PKs to `INT GENERATED BY DEFAULT AS IDENTITY`.
5. Normalize `INTEGER` → `INT` and `VARCHAR(50)` → `TEXT`.
6. Rename the two abbreviated indexes to their full-column-name form.
7. Remove the stray whitespace.
8. Add `COMMENT ON COLUMN` for all uncommented `tisch_sessions` and
   `tse_signaturen` columns, in the file's existing style and language mix.

Finish with `make sqlc`: the generated code in `backend/sqlc/dbgen/` must come out
diff-free, demonstrating none of the changes alter what the application sees.
