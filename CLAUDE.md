## Claude Code

- In Cloud-Sessions (claude.ai/code, erkennbar an `CLAUDE_CODE_REMOTE=true`): fehlende Dev-Tools mit `bash scripts/setup-dev-tools.sh` installieren; PostgreSQL ist vorinstalliert, aber gestoppt (`service postgresql start`).
- Handbook-Plugin (`handbook@nicograef`, Marketplace-Repo `nicograef/handbook`): lädt in Cloud-Sessions nur, wenn `nicograef/handbook` beim Session-Start im GitHub-Scope der Session liegt — sonst blockiert der Git-Proxy den Marketplace-Clone und die `/handbook:*`-Skills fehlen. Dauerhafter Fix: das Repo als zusätzliche Quelle in der Cloud-Umgebung/Session hinterlegen. Workaround in laufender Session (hiermit autorisiert): `nicograef/handbook` per `add_repo` hinzufügen, klonen, `register_repo_root` aufrufen und die Skills aus `<clone>/.claude/skills/` direkt befolgen.
- Kein Fable: Fable (`fable`, Fable 5, `claude-fable-5`) wird nicht verwendet — weder für die Session noch für Subagenten, Tool-Aufrufe, Konfigurationsdateien oder Vorschläge; der Preis rechtfertigt den Zusatznutzen hier nicht. Es gibt nur zwei Stufen: Opus 5 (`claude-opus-5`) und Sonnet 5 (`claude-sonnet-5`).
- Subagenten-Modellwahl: Worker-/Reviewer-Subagenten (Agent-Tool `model`-Parameter, Workflow `agent()`-Option `model`) erben nie stillschweigend das Top-Level-Modell. Pro Aufgabe entscheiden: `sonnet` (Sonnet 5) für mechanische, klar spezifizierte Arbeit (Exploration/Suche, Umbenennungen, Formatierung, Doku-Sweeps, Boilerplate, einfache Fixes), `opus` (Opus 5) als Standard-Worker und zugleich oberste Stufe (Implementierung, Review, Verify, Debugging sowie die härtesten Reasoning-Aufgaben: Architektur, subtile Korrektheitsanalyse, finale adversariale Verifikation). Forks erben immer das Parent-Modell — nie forken für Arbeit, die `sonnet` erledigen kann.
